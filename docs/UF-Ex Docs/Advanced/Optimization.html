Preface

Suppose you had completed the previous tutorials or already have decent amount of experience in using UF-Ex, you should have quite an amount of code that you had made previously. It is likely that you have developed a mindset "if it works, don't touch it". While this is the safe play, it is not suited for long term development, and we aim to be better than just having the codes work.

What is optimization

Imagine you are solving a math problem during an exam, you would want to solve it as fast as possible and move on to the next question right? Coding is basically the same, it's best to execute codes as fast as possible so it can run more codes in 1 frame.

However, speed isn't everything. Let's say you can bring a cheat sheet to the exam, and of course the fastest way to complete the exam is to have all the answers written on the cheat sheet beforehand. But of course, if there are 100 questions, the cheat sheet will be very messy, if it can even contain all the answers. In coding, the cheat sheet is the Memory stored in RAM. Grabbing data from memory would be fast, but it's not ideal to put a lot of data into memory just so some code can run a bit faster.

Optimization in games is to reduce the time for the CPU to process the game's logic, reduce the time for the GPU to render the game's graphics, and to reduce the memory usage in RAM. In other words, make the game less likely to lag. While yes, you may think that because it didn't lag on your computer, then the code is fine. That is not true, it didn't lag on your computer, but there is no guarantee that other people won't experience lag, so it is best to optimize the codes so the chance of lagging reduces.

Step 0: Benchmarking

So now you understand why should we make codes run faster, but how do we know whether the code did run faster? Of course, you can always use the built-in profiler to check the CPU usage and the Memory Usage, but that's not enough, it is strongly recommended that you install BenchmarkDotNet to your solution so that you can effectively identify what codes need improvement and whether the new ones are improvements at all.
